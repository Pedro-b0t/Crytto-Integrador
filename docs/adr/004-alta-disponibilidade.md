# ADR-004: Estratégia de alta disponibilidade

No contexto de uma aplicação acadêmica que, na primeira entrega, utilizava uma única zona, uma VM de aplicação e uma VM de banco de dados, diante da necessidade de reduzir os pontos únicos de falha e melhorar a continuidade do serviço, decidimos propor uma arquitetura de alta disponibilidade na região `us-central1`, com duas VMs de aplicação distribuídas entre as zonas `us-central1-a` e `us-central1-b`, um Load Balancer HTTPS com health checks, Cloud NAT gerenciado e compartilhado para as sub-redes privadas e Cloud SQL PostgreSQL com alta disponibilidade regional, e descartamos manter toda a aplicação em uma única zona, utilizar uma VM própria como NAT e continuar com o banco de dados sem réplica, para permitir que a aplicação continue atendendo aos usuários caso uma das VMs falhe, melhorar a recuperação do banco e manter as instâncias de aplicação sem IP público, aceitando que essa solução possui custo mensal mais elevado, maior complexidade de configuração e ainda apresenta limitações, como o bastion único e possíveis falhas regionais. Considerando o uso acadêmico e o orçamento limitado, essa arquitetura será apenas projetada nesta entrega, sem implantação na Google Cloud.
